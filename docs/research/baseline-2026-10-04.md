**Purpose:** freeze the **0.3.0** numbers that the engine-sharding release (#133, S5) is judged
against, with the predictions stated in advance (#126). D008 pins the before-baseline to the release
installed immediately before the sharding cut, which is 0.3.0. **This is not `baseline-2026-08-25.md`

## Units, and what P2 is

- **P2 (ingested)** is in **context tokens**: the context-window deltas `engine_cost.py` attributes
  to engine reads. It is *not* `chars/4` and *not* the file size. One complete 0.3.0 load ingests
  ≈102,000 context tokens, ≈0.381 per engine byte.
- **P2 means all engine text the parent loads: core plus units.** On 0.3.0 that is `loop-engine.md`
  alone, since there are no units. **`engine_cost.py` counts only `loop-engine.md` reads**, so before
  #133 measures, it must be extended to count `phases/` and `reference/` reads. Otherwise deferral
  reads as deletion.
- **P2c** is `resident_turns / processed`. It is dimensionless and turn-invariant, and it is #133's
  primary acceptance metric.
- **No P2-to-always-loaded ratio is stated here.** The unit of that ratio's denominator is #223's open
  question, and #133 accepts on nothing that divides by it.

## Instrument fix (#126)

`classify()` treated any path containing `/plugins/` as a plugin-cache **load**. Since #170 the
working tree itself sits under `plugins/dev-loop/`, so in-repo engine reads in `claude-code-loop`
sessions were scored as loads. Two qualifying sessions were inflated:

| session | P2 before fix | after |
|---|---:|---:|
| `de7e4367` | 127,654 | 101,828 |
| `b5129651` | 112,120 | 101,944 |

The loop P2c median moved 32.8% → 31.0%. The discriminator is now `/.claude/plugins/cache/`, pinned
by `test_payload_working_tree_read_is_tree_not_load` in `test_engine_cost.py`. vote and esg were
unaffected. **#133's after-side would have hit this harder**, since its units also live under
`plugins/`.

## Predictions for the sharding release, stated in advance

Each prediction is stated against **this** baseline, per repo, using the in-tree sizes at `3725ee5`
(core 200,789 B; `reviewing` 32,344 B, loaded at step 8; `accepting` 38,409 B, loaded at step 10).
**If the release commit's sizes differ, re-derive from the same formulas**, which are stated so that
can be done mechanically. The model is: ingestion scales with bytes loaded at ≈0.381 context tokens
per byte (the measured 0.3.0 rate in all three repos).

| # | metric | 0.3.0 baseline (loop · vote · esg) | predicted | how |
|---|---|---|---|---|
| P1 | always-loaded | 277,829 B | **211,618 B (−23.8%)** | `wc -c` |
| **P2** | ingested, full iteration | 101,967 · 102,113 · 101,989 | **≈103,500 in each: unchanged (+1.5%)** | core + both units ≈ 1.015 × 0.3.0 bytes |
| P3 | ingested, plan-gate stop | not measured (n=1) | **≈76,500 (−25%)** | core only ≈ 0.750 × 0.3.0 bytes |
| **P2c** | resident/processed | 31.0% · 29.0% · 34.9% | **27.4% · 25.6% · 31.1%** (bounds 25.2–31.3 · 23.5–29.3 · 28.7–35.2) | see below |
| P9 | compactions | 0 · 0 · 0 | **unchanged** | — |
| P5–P7 | confounded | above | **unchanged; a drop is a red flag** | — |

- **P2 does not fall for a full iteration. That is the design, not a failure.** Sharding defers text;
  it does not delete it. An iteration that reaches steps 8 and 10 loads all of it: 1.5% more bytes in
  total than 0.3.0's single file. **P2 falling for full iterations would mean units are not being loaded when
  due**: the gate that reads them is being skipped. The saving shows up in P3 and P2c, never in P2.
- **P2c model.** Engine resident-turns scale by `k`, and the rest of the context is unchanged, so
  P2c′ = s·k / (1 − s + s·k), where s is the baseline P2c.
  - **Lower bound:** units never loaded, k = 0.750.
  - **Upper bound:** units loaded at the first turn, k = 1.015.
  - **Point estimate:** `reviewing` arrives 55% of the way through a session's turns and `accepting`
    at 75%, so k = 0.840. #133 measures each unit's real arrival centroid. **If the centroids differ,
    re-derive the point estimate from them before judging.**
  - A P2c *below* the lower bound means less engine was resident than core alone, so something
    failed to load. That is a red flag, not a larger saving.
- **Read P2c per repo against its own baseline.** Medians across these strata or across repos are
  meaningless here (D007).
